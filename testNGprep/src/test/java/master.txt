--------------------------------------------------------------------
                                Assertions
--------------------------------------------------------------------


assertion - validations
whenever a test is passed or failed only that result should come on report
Assert class

instead of conditional statements/loops use assertion statements only assertion statements can
make our statements pass or fail

-> we can use assertion along with conditional statements also if required
put the assertions with test conditions methods and it will help to validate

Assert.assertEquals(s,s2);
Assert.assertTrue(true);

2 kinds
     1. Hard assertions
     2. soft assertions

when importing classes and it's methods some of the methods are present in junit also with same name
look clearly and import org.testng

 Hard assertions - are static classes and the method directly access from assert class directly

 limitations :
 When assertions methods got failed the next statements will not be executed
 statements/remaining code after the validation(assertion) will not execute

so in test methods the last statement should be used for validation (assertions)
so even if that is failed nothing left after the assertions so we put them in the last

in case if we need to execute any statements after assertions we use soft assertion
so even if validation/assertion failed the next statements execute

in hard assertion we call method directly, instead we create object of SoftAssert class and create it's object
and access all the methods same methods present in both hard and soft assertions

at the end all at last we write "sa.assertAll()". -> otherwise it will always pass
soft assertions by default pass

--------------------------------------------------------------------
                                dependency Methods
--------------------------------------------------------------------

if one method is dependent on other method
we don't need to unnecessarily execute all the methods only the methods which are dependents
should be passed then only the following methods will be executed

if the dependent method test got failed then the that method will be skipped

if other test methods which dont have any dependency those will be executed normally

for single - @Test (dependsOnMethods = {"method name"})

@Test(priority = 3, dependsOnMethods = {"login"})
    void search(){
        Assert.assertTrue(true);
    }

for multiple - @Test (dependsOnMethods = {"method name", "method name"})

@Test(priority = 4, dependsOnMethods = {"login", "search"})
    void advSearch(){
        Assert.assertTrue(true);
    }

--------------------------------------------------------------------
                                grouping methods
--------------------------------------------------------------------
if we to execute test methods based on groups

class1 - > m1, m2,m3..
class2 - > m4, m5, m6..
class3 - > m7, m8, m9..

if we want to execute for different test suites/cases based on groups

loginGoogle, loginApple, loginTwitter - sanity (group)
signUpGoogle, signUpApple, signUpTwitter - regression (group)
googlePay, applePay, twitterPay - sanity, regression (group)

single and multiple groups

@Test(priority = 1, groups = {"sanity"})
    void loginGoogle(){
        System.out.println("logged in with Google...");
    }

 @Test(priority = 2, groups = {"regression"})
    void signUpApple(){
        System.out.println("signed up with Apple...");
    }

@Test(priority = 3, groups = {"regression", "sanity"})
    void twitterPay(){
        System.out.println("paid through twitter - cryptos...");
    }

inorder to execute the test methods we need to use testNG.xml - (xml files)

<groups>
            <run>
<!--                <include name="sanity"/>-->
<!--                <include name="regression"/>-->
                <exclude name="regression"/>
<!--                <include name="functional"/>-->
            </run>
</groups>

include - includes with single groups that single name and multiple names (matches) - (kind of like OR operator)
both single and multiple groups will considered for execution

@Test(priority = 1, groups = {"sanity"})
    void loginGoogle(){
        System.out.println("logged in with Google...");
    }

 @Test(priority = 2, groups = {"regression", "sanity", "functional"})
     void applePay(){
         System.out.println("paid through apple pay...");
     }

exclude - excludes with single groups that single name and multiple names (matches) - (kind of like OR operator with not)
both single and multiple groups will considered for execution

 @Test(priority = 2, groups = {"regression"})
    void signUpApple(){
        System.out.println("signed up with Apple...");
    }

@Test(priority = 2, groups = {"regression", "sanity", "functional"})
    void applePay(){
        System.out.println("paid through apple pay...");
    }

if we want to get both sanity or regression - it's not possible if we include both in group it will execute both sanity and regression
so better we create/use another name here it's functional.

@Test(priority = 1, groups = {"regression", "sanity", "functional"})
    void googlePay(){
        System.out.println("paid through gPay...");
    }

we can use include and exclude combination also like include sanity and exclude regression

--------------------------------------------------------------------
                                Data Providers
--------------------------------------------------------------------


1. @DataProvider - data driven testing
data driven we read data from excel file and read the data and passed it to application
after that we fetech data from application (capture some data)and passed to application -> we use loops
instead of loops we use @DataProvider annotation

we can avoid writing a loop statements
inside data provider we provide test data it has logic and keeps in 2d array
as soon as we read the data from excel file we put them in 2d array then pass data to test method
so that it will repeat multiple times without loop and taking data from excel
can be used for single and multiple test methods
it will just provide data to applications (@Test) methods

we can have multiple data providers in a single class
and we can pass multiple data providers to multiple test methods

the @DataProvider method return type will be a two dimensional array the data type can be String[][], Integer[][] or we can also use Object[][]
sometimes the test data have string, number different combinations so better we use Object[][] data type

it can be a 2D array and returns string or object... like that

excel files and property files -> web automation testing
json files, xml files -> api testing

we need to give name to @DataProvider method and pass that name to @Test method

@DataProvider(name = "dp")
    Object[][] loginData(){

full xml -
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE suite SYSTEM "https://testng.org/testng-1.0.dtd">
<suite name="parallelTesting" verbose="2">
    <test name="MultipleBrowser">
        <parameter name="browser" value="chrome"/>
        <classes>
            <class name="parameterization.paramTest"/>
        </classes>
    </test>
</suite>

------------- parallel execution ----------------------

here we need to tell to suite parallel="tests" - as we need to run all 3 test together at once we use parallel="tests" at suite level

<suite name="parallelTesting" verbose="2" parallel="tests">

we can use this at class level also
inside test we have classes so if we want to execute all classes at once we use parallel="classes"
-> parallel="classes"
<test name="chromeTest" parallel="classes">

but it's a rare case we only need to execute tests parallel(together all at once) so we use parallel="tests"
in our case both chrome and edge browsers will run at same time as we follow parallel execution rather than sequential/serial execution

--------------------------------------------------------------------
                             testNG listeners/post actions
--------------------------------------------------------------------

testng listeners -> when run test cases (pass/fail/skip)
based on result we perform some action called post actions
based on execute status of test methods (pass/fail/skip) execution is done - we perform certain actions
those are post actions

actions if test method like pass -> post action is update results in report (post actions)
if test method failed -> take screenshot and update in report (post actions)
skipped -> update in report (post actions)

to perform post action we use listeners
create listeners class -> implements ITestListener interface
implements those interface methods in our listeners class implement as per our requirement
in xml we have specify listeners class

1. create test case
2. create listener class and implement ITestListener interface and it's methods
3. create xml file include both test case and listener class

and execute so after our test case methods pass/fail/skip -> listeners class will perform post actions

2 ways to implement listeners class
1. implement ITestListener interface
2. extend TestListenerAdapter

both we can use difference there some default methods that are extracted to the implemented class TestListenerAdapter
we go with implementing ITestListener interface - documentation : https://javadoc.io/static/org.testng/testng/7.9.0/org/testng/ITestListener.html

implement methods like :
onStart(ITestContext context)           -----------------> start of class
onTestStart(ITestResult result)         -----------------> start of test methods (test cases) - (happens for all test methods)
onTestSuccess(ITestResult result)       -----------------> if test methods passed (test cases)
onTestFailure(ITestResult result)       -----------------> if test method failed (test cases)
onTestSkipped(ITestResult result)       -----------------> if test method skipped (test cases)
onFinish(ITestContext context)          -----------------> end of class

in the xml file we need to create listeners tag and all listener file path
we shouldn't include this along with normal class, we should have a separate entry in xml file
in xml file we can have multiple classes but for all classes there can be only one listener class -> reason basically it used to do post actions which works fine for all classes
it check through file it's basically a utility file for generating a report

<listeners>
        <listener class-name="testNGListeners.listeners"/>
    </listeners>

full xml -
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE suite SYSTEM "https://testng.org/testng-1.0.dtd">
<suite name="listeners" verbose="2">
    <listeners>
        <listener class-name="testNGListeners.listeners"/>
    </listeners>
    <test name="LoginTest">
        <classes>
            <class name="testNGListeners.orangeHRMLogin"/>
        </classes>
    </test>
</suite>


we can use 2 approaches
 1. with xml file pass listeners class and our class and it will do post actions
 2. instead of using xml, go to the class and use @Listener annotation -> @Listeners(listeners.class)

in the class we write @Listeners(listeners.class)
but out of those 2 we use xml approach because if we use annotation approach we have to write manually for all classes
but with xml we just write once in listeners and include with the classes.
